# Phase 1 / 1B — ADALM-PLUTO Detection and Unique-Device Identification

**Status:** PASS  
**Date:** 2026-05-10  
**Prerequisite:** libiio and pyadi-iio installed; both PLUTOs connected via USB hub

---

## What was done

Phase 1 confirmed that the Python environment (pyadi-iio, pylibiio) could reach
at least one ADALM-PLUTO via IIO context probing. Phase 1B extended this to
fingerprint each device by `hw_serial` and prove that the two PLUTOs attached
to the hub are physically distinct devices.

An initial run found only one device. After replacing a suspect USB cable, a
second run detected both PLUTOs and confirmed two unique `hw_serial` values.
The conclusion `TWO_UNIQUE_DEVICES_CONFIRMED` was recorded.

## Key findings

- Pluto A: AD9364, firmware v0.39, serial `1044734c9605000308000b003535507e9e`, preferred URI `ip:pluto.local`
- Pluto B: AD9363A, firmware v0.38, serial `1044734c96050007e9ff160082b24f2149`, preferred URI `ip:192.168.2.1`
- USB bus-path URIs (`usb:1.x.x`) are unstable — Windows re-enumerates the hub on reconnect. `hw_serial` is the authoritative identity; IP URIs are the preferred runtime addresses.
- A suspect USB cable was the root cause of the initial one-device detection failure (Decision 10).

---

## Limitations

- Detection is read-only; no hardware settings are changed.
- `hardware_status.md` is regenerated by `00_list_plutos.py` and reflects the state at the most recent run.
